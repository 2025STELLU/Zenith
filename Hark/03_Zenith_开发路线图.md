# Zenith 开发路线图（Development MAP）

> 基线：`0.1.1-alpha`（NeoForge 1.21.1）
> 依据：文档 01（全模组审计）、文档 02（特效与渲染专项）
> 原则：**先正确，再可见，再好玩，再精深**

---

## 0. 定位与愿景

**一句话定位**：Minecraft 里"可信、可见、可玩、可被其他模组调用"的风与天气基础设施。

| 维度 | 现状 | 1.0 目标 |
|------|------|------|
| 可信 | 多尺度骨架有，但坐标、时间、高度、插值、生命周期问题导致结果失真 | 物理方向全部正确；关键模型有文献依据与回归测试；多人可用 |
| 可见 | 只有粒子与一个龙卷网格；台风/雷暴在世界里看不见 | 局地降水、风暴云、龙卷、台风结构、雾、天空与声音完整联动 |
| 可玩 | 帆船上不去船、风扇关不掉、方块无法在生存获得 | 帆船/滑翔/风能/天气灾害形成完整玩法闭环 |
| 可调用 | API 形态好但策略被忽略、部分接口是占位 | 版本化的稳定 API + 事件 + 批量采样 + 客户端 API + 文档与示例 |

**差异化**：与"纯视觉天气"（多数天气模组）和"纯灾害玩法"（如 Weather2）相比，Zenith 的护城河是**多尺度风场 + 服务端权威 + 开放 API**。路线图的所有阶段都围绕"让其他模组愿意依赖 Zenith 的风"展开。

## 3. 0.2 正确性与基础设施

### 3.1 统一约定（Epic: Conventions）
- 新增 `Atmos` 工具类：`solarElevation()`、`cyclonicTangent()`、`geostrophic()`、`taper()`、`agl()`；全仓替换 7 处日相位与 3 处旋转（SYS-01/02）。
- 半球配置（默认北半球），以及"世界尺度"常量 `METERS_PER_BLOCK`、`TIME_SCALE`（游戏 1 天 = 20 分钟意味着日变化被压缩 72 倍，需要统一定义哪些过程跟随游戏时间、哪些跟随真实时间）。
- 气象约定文档：风向表示（去向/来向）、角度零点、单位（m/s、K、Pa）、坐标轴。

### 3.2 垂直结构与插值（Epic: Grids）
- L1 改为**离地（AGL）拉伸分层**，三线性插值；层顶以上回到自由大气（L1-01）。
- L0/L1/海风/客户端所有场改为插值采样，域外返回"无贡献/回退上层"，不再夹边外推（SYS-05）。
- 所有现象改用 AGL，外缘 C¹ 平滑包络（SYS-03、TY-02/03、SQ-02/03、DD-01）。
- L0 平移改为数组移位 + 新格初始化，焦点对齐 256 格（L0-02）。
- 步长无关化：所有"每次调用固定量"改为 `1−exp(−dt/τ)`（L0-03）。

### 3.3 L2 急救（Epic: Local Flow）
- 地面排除、归一化与限幅、扫描边缘平滑（L2-01 短期方案）。
- 结果缓存 `(blockPos, L1 epoch)`；风道只读上游（L2-04）。
- 热源改为事件驱动登记（L2-03）。

### 3.4 运行时与服务器友好（Epic: Runtime）
- 维度门控 + 白名单配置（SYS-09）。
- 所有世界查询区块安全化；闪电仅在已加载区块落地，远处闪电改为客户端视觉（SYS-10）。
- 海风距离场预计算缓存（SB-05）；重计算分帧（time-slicing）。
- `SavedData` 持久化驱动器与现象；随机源由种子派生（SYS-08）。
- 配置（`ModConfigSpec`）：服务端（闪电点火、冰雹伤害、现象开关与上限、刷新频率、维度）、客户端（粒子档位、渲染档位、声音）。

### 3.5 测试与工具（Epic: QA）
- JUnit 纯物理测试（不启动 MC）：
  - 手性测试：北半球低压中心东侧的风必须指向北（−Z）；
  - 日相位测试：dayTime=6000 时 `solarElevation≈1`，18000 时 ≈−1；
  - 连续性测试：沿半径扫描台风/龙卷/尘卷风，相邻 0.5 格风速差 < 阈值；
  - L2 平地测试：平地 1.6 格高度 |w| < 0.5 m/s；
  - 线走向测试：飑线方向与引导风夹角 90°±5°；
  - 极线测试：NACA 0012 在 0° 的 Cl = 0、cd(90°) ∈ [1.6, 2.1]。
- NeoForge GameTest：放置风扇→关闭→射流消失；帆船可乘坐并在横风下前进。
- 开发者命令：`/zenith debug dump <x z>`（输出各层贡献）、`/zenith profile`（各子系统 ms）。
- CI（GitHub Actions）：构建 + 测试 + 产物上传。

**验收**：文档 01 中所有 P1 以上的物理问题关闭；单人默认设置下 Zenith 服务端平均开销 < 0.5 ms/tick、最大尖峰 < 5 ms。

## 5. 0.4 多人与可扩展

### 5.1 世界锚定瓦片（Epic: Tiling）
- L1 改为按世界坐标对齐的瓦片（如 16×16 列/瓦片），每名玩家激活周围瓦片，LRU 回收；L0 可保持单一大网格或也瓦片化。
- 天气现象的生成锚点基于"活跃瓦片集合"而非随机玩家，实现密度均匀。
- 粗风场与快照按玩家距离裁剪、增量发送（只在变化时）。
- **验收**：两名玩家相距 20,000 格时，各自的风场与单人时一致；服务器 20 人在线时 Zenith 开销 < 2 ms/tick。

### 5.2 API v1（Epic: API）
- `ZenithApi.VERSION`、语义化版本承诺。
- 真正实现 `SamplePolicy`；`Source` 改为位集合；`confidence` 有实际含义（例如数据新鲜度、是否在网格内）。
- `sampleBatch(world, double[] xyz, policy)`；只读快照（线程安全，供工作线程使用）。
- 事件（NeoForge 游戏总线）：`ZenithWeatherEvent.PhenomenonSpawn/Despawn`、`TyphoonLandfall`、`LightningStrike`、`HailStart`、`FrontPassage`（可用于成就、红石、其他模组联动）。
- 客户端 API：`ZenithClientWindApi` 返回 ClientAtmosphere 的结果；提供"推荐视觉响应函数"（旗帜、风车、绳索）。
- `runPolar` 修正（薄翼理论 α0、Viterna 失速外推、Re 修正）；`runL2` 未实现前返回 `unsupported`。
- API 文档站 + 示例模组（"风车示例"、"旗帜示例"、"滑翔机示例"）。

### 5.3 数据驱动（Epic: Data）
- 天气现象参数（强度区间、寿命、生成条件、生物群系权重、命名表）放进数据包 JSON（`data/<ns>/zenith/phenomena/*.json`），服务器管理员和整合包作者可调。
- 生物群系 → 地表类型/粗糙度/反照率/热容的映射用标签与 JSON 配置，自动支持其他模组的生物群系（Biomes O' Plenty、Terralith 等）。

## 6. 0.5 玩法

| 系统 | 设计要点 | 依赖 |
|------|------|------|
| **帆船 2.0** | 船体坐标系分解；帆 = 翼型（复用 `runPolar`），龙骨侧力；横倾；碰撞与搁浅；客户端控制者权威 + 服务端校验；帆布渲染 | 0.2 极线修正、L1 近地风正确 |
| **滑翔机 / 滑翔翼 / 鞘翅增强** | 热泡、背风波、山脊上升气流（坡面 `w = V·∇h`）可被利用；鞘翅在上升气流中获得升力（可配置） | 热泡/背风波修正 |
| **风筝 / 风向袋 / 旗帜** | 低成本、高"风感"的装饰与红石元件 | 客户端 API |
| **风能** | 风车/风力涡轮（按功率曲线 `P = ½ρAv³Cp`，Cp≤0.593 Betz 极限）；兼容 Create（应力单位）、Forge Energy | 玩法采样、L2 遮挡（风电场尾流效应！） |
| **天气灾害**（可配置） | 强风吹落树叶/作物倒伏、龙卷卷起实体与松散方块（受保护区与 gamerule 约束）、冰雹砸碎玻璃/农作物、雷击引火受 `doFireTick` 约束、沙尘暴降低能见度与生物刷新 | 配置系统、区块安全 |
| **气象仪器** | 气压计（L0 气压趋势→天气预报）、湿度计、雨量计、风廓线雷达（显示垂直风廓线）；可输出红石 | API 指标 |
| **天气预报** | 基于驱动器与现象的确定性外推给出 +1/+3/+6 游戏小时预报，气象图展示；"预报失误"由随机扰动自然产生 | 持久化与确定性随机源 |
| **弹射物与实体漂移** | 箭、雪球、三叉戟、掉落物、气球类实体受风偏（可配置强度） | 批量采样、缓存 |
| **火势与烟** | 火焰蔓延方向偏向下风；烟柱随风倾斜 | — |

## 7. 0.6 数值内核

| Epic | 内容 | 备注 |
|------|------|------|
| L0 动力学升级 | 浅水方程（线性化重力波 + 科里奥利 + 平流），半隐式时间积分；气压与风自洽，取消"驱动器目标风 vs 地转风"的混合 | 物理一致性的根本解决 |
| L1 预报化 | 2.5D：每列多层，水平平流 + 垂直混合（K 理论，K 由稳定度与风切变决定）+ 地形强迫；保留状态而非纯诊断 | 时间连贯的阵风/锋面过境 |
| 湿热力学 | 位温 θ、比湿 q，凝结（饱和调整）→ 云水 → 降水（Kessler 暖云简化），CAPE 简化指标；风暴单体的生成/强度由 CAPE × 切变 × 抬升 决定 | 使"湿度不够就不打雷"成为物理结果 |
| 冰雹与雷电 | 冰雹尺寸由上升气流强度决定（经验关系）；闪电频率与上升气流/冰相含量相关 | 灾害玩法的依据 |
| 锋面热力学 | 锋面作为 L0 温度/湿度场的不连续面注入，风向转变自然产生 | 取代纯动量的锋面 |
| 异步 L2 数值求解 | 每个"活跃局部域"（如 48³ 体素）在工作线程运行 Stable Fluids（Stam 1999，无条件稳定）或 D3Q19 LBM；双缓冲，主线程只读最近完成的结果；方块变更增量更新体素 | 风扇/建筑/风道获得真正的绕流、涡街与遮挡；JDK 21 可评估 Vector API（孵化）加速 |
| 确定性 | 固定种子 + 固定步长 + 可重放日志，便于多人一致与 bug 复现 | — |

**性能目标**：异步 L2 单域 48³ 在 4 核机器上 ≥ 10 Hz；主线程开销不增加。

## 8. 0.7+ 电影档与生态

- 体积云 / 风暴云光线步进（T3，可选，光影激活时自动关闭）。

- 更多现象：雪暴（风吹雪、白化）、冻雨（地面结冰）、龙卷群、海龙卷、热带风暴的眼墙置换、焚风（下坡增温干燥）、山谷风环流、城市热岛（大量人工方块区域）。
- 多版本：抽象后的渲染后端支持 1.21.5+ 的 `RenderPipeline` 与 1.21.9+ 的提取/提交；评估 Fabric 版本（Architectury 或 MultiLoader 模板）。
